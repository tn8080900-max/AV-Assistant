Build a Windows-compatible voice-controlled AI personal task agent called **AV Assistant**.

## 1. Main Goal

Create a working application that allows me to communicate with an AI entirely through voice.

The user should be able to:

1. Press a microphone button or activate voice input.
2. Speak a command.
3. Convert the speech to text.
4. Send the request to an AI model.
5. Let the AI determine whether it needs to use a tool.
6. Execute approved tools.
7. Return the result.
8. Convert the AI's response to speech.
9. Play the response through the computer speakers.

The architecture must be designed so that the application can later become a much more capable computer-control and IoT agent.

Do NOT build a simple chatbot only. Build the foundation of an actual AI agent with tools, permissions, memory, and an extensible architecture.

---

# 2. Technology

Use a technology stack that is practical for running on Windows.

Prefer:

* Python for the backend/agent
* A lightweight web frontend for the user interface
* FastAPI for the backend API if appropriate
* HTML/CSS/JavaScript for the frontend if a separate frontend is useful
* Environment variables for API keys
* Modular Python files rather than putting everything into one file

Choose stable libraries that are well supported.

Do not hard-code API keys or secrets anywhere in the source code.

Create a `.env.example` file showing the required environment variables.

---

# 3. Voice Input

Implement speech-to-text.

The application should:

* Request microphone permission when necessary.
* Provide a microphone button.
* Show a clear recording state.
* Allow the user to start and stop recording.
* Convert recorded speech into text.
* Display the recognized text before sending it to the AI.
* Handle speech-recognition errors gracefully.

The architecture should allow the speech-to-text provider to be replaced later.

Do not permanently tie the entire application to one speech-recognition provider.

---

# 4. AI Agent

Create an actual agent loop.

The basic flow should be:

USER VOICE
↓
SPEECH TO TEXT
↓
AI AGENT
↓
DECIDE WHETHER A TOOL IS REQUIRED
↓
TOOL EXECUTION
↓
OBSERVE RESULT
↓
AI AGENT
↓
FINAL RESPONSE
↓
TEXT TO SPEECH

The AI must be able to decide when to use a registered tool instead of simply generating text.

Implement tools through a clear tool interface so that new tools can be added later without rewriting the agent.

For example:

```python
class Tool:
    name
    description
    parameters
    execute()
```

Use an appropriate structured tool/function-calling mechanism supported by the selected AI provider.

# 5. Initial Tools

For the first version, implement safe basic tools.

### Tool 1 — Get current time

Example:

User:
"What time is it?"

Agent:
Uses the time tool and responds with the current time.

### Tool 2 — Calculator

The agent should be able to perform mathematical calculations through a calculator tool instead of relying on language-model arithmetic.

### Tool 3 — Open a website

Allow the agent to open a URL in the default browser.

Example:

"Open Google."

The agent should determine that opening a website requires the browser tool.

### Tool 4 — Open an application

Create a Windows application-launching tool.

Example:

"Open Notepad."

The tool should use a controlled list of permitted applications rather than allowing arbitrary shell commands.

### Tool 5 — File search

Create a tool that can search user-selected directories for files.

Initially, restrict file access to directories explicitly configured by the user.

Do NOT give the AI unrestricted access to the entire computer.

# 6. Permission System

This is a critical part of the application.

The AI must NOT automatically perform potentially consequential actions.

Create a permission system.

Classify tools into:

### SAFE

Examples:

* Getting the time
* Calculator
* Reading a non-sensitive configured file
* Opening a permitted application

These can execute automatically.

### REQUIRES_CONFIRMATION

Examples:

* Sending a message
* Submitting a form
* Deleting a file
* Moving or renaming important files
* Making purchases
* Changing system settings
* Executing arbitrary commands
* Controlling external devices

Before executing one of these actions, the agent must stop and ask the user.

Example:

"You're asking me to delete `example.pdf`. Do you want me to continue?"

The UI should provide:

**ALLOW**

**DENY**

The action must not happen until the user explicitly approves it.

---

# 7. Security

Security is extremely important.

Do NOT create unrestricted:

```text
os.system(user_input)
```

or equivalent arbitrary command execution.

Never directly treat AI-generated text as a shell command.

All computer actions must go through registered tools.

Use:

* Tool allowlists
* Parameter validation
* Path validation
* Permission checks
* Confirmation dialogs
* Safe error handling

Prevent path traversal such as:

```text
../../
```

when accessing configured files.

The AI should not be able to access passwords, credentials, API keys, browser cookies, or other sensitive data unless a future feature explicitly and safely supports it.

For Version 1:

* Store session conversation history.
* Provide a clearly separated memory module.
* Make it possible to add persistent memory later.

Create an interface such as:


# 19. Future Architecture

Design the system so that these can be added later without rewriting the entire application:

### Computer control

The agent should eventually be able to:

* See the screen
* Click
* Type
* Scroll
* Navigate applications
* Interact with websites

Every consequential action must remain subject to the permission system.

### Browser agent

Eventually allow:

"Search the web for X."

"Open this website."

"Fill this form."

"Download this file."

"Summarize the page."

Actions such as submitting forms should require confirmation.

### IoT/device control

The architecture should eventually support external devices.

Potential future tools:

```text

device_control()
```

* Device

# 20. Important Design Principle

This project is NOT intended to be a fake demo.

Build a functioning minimum viable product.

Do not merely create buttons that pretend to perform actions.

If a capability cannot be implemented in the current environment, clearly document it and create the correct interface/stub for future implementation instead of pretending it works.

# 21. AI Behavior

Use a strong system prompt for the agent.

The agent should:

* Understand natural language.
* Break complex tasks into steps.
* Use tools when appropriate.
* Avoid unnecessary tool calls.
* Never claim that an action was completed unless the tool actually reports success.
* Ask for clarification when a command is ambiguous.
* Ask for permission when required.
* Explain failures honestly.
* Never bypass the permission system.
* Never invent tool results.

Example:

User:
"Open my physics notes."

Agent:
Searches the configured directories.

If one matching file exists:
Open it.

If multiple files exist:
Ask which one.

If no file exists:
Tell the user that no matching file was found.

# 24. Development Approach

Build this incrementally.

First make:

```text
Voice input
↓
Speech-to-text
↓
AI
↓
Text response
↓
Text-to-speech
```

Then add the tool system.

Then add the permission system.

Then add safe computer tools.

Do not attempt to implement every future feature at once.

After each major stage, run tests and fix errors before continuing.

The final result should be a functioning Version 1 voice-controlled AI agent with a clean foundation for future computer control and IoT capabilities.
